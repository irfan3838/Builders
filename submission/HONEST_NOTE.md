# Honest note: built, reused, simulated

## What we built at the event
The application was written during the hackathon with **Claude Code (an AI coding agent), under the builder's direction**. The builder chose the product, the scope, the features, the roles, the UX and the design direction, and reviewed and tested by voice. Claude Code wrote most of the code. Independent Claude Sonnet agents wrote and ran the automated tests. The file-by-file log is in [`docs/AUTHORSHIP.md`](../docs/AUTHORSHIP.md).

Built at the event:
- The FastAPI backend, the proposal → confirm → receipt engine, the append-only budget and leave ledgers, the audit trail and document intake.
- The OpenAI Agents SDK agent (102 typed tools), the **checklist workflow engine** (67 workflows, picker, verification, kill, escalation) and user routines.
- The voice bridge (GPT-Live over WebRTC, Python sideband, server-observed confirmation) and the Hindi/Hinglish/English affirmation classifier.
- Agent-built charts (typed ChartSpec → vetted SQL), people ops, Gmail/Calendar integration, travel search and contract liability reading.
- The React + three.js UI (visual direction from a reference screenshot supplied by the builder).
- The eval harness and 46 scenarios, Terraform for AWS, and the deploy scripts.

## What we reused
- **Budget, revenue and contract-scanning logic** from the builder's earlier work, adapted and integrated here (listed in `docs/AUTHORSHIP.md`).
- **Open-source libraries:** FastAPI, SQLAlchemy, Alembic, Pydantic, OpenAI Python SDK and Agents SDK, pypdf/pypdfium2, React, Vite, three.js, Motion, ECharts, lucide-react.
- **External APIs:** OpenAI (voice, agent, vision), Google Gmail and Calendar, SerpAPI (Google Flights/Hotels), Frankfurter (ECB FX rates), LangSmith (tracing).

## What is simulated
- **All company data is synthetic:** the workspace, 26 employees, vendors, clients, bills, invoices, claims, contracts and inbox messages. It was generated by `seed/` scripts. No real customer or employee data is used.
- **Jul–Sep 2026 budget actuals** are a synthetic "imported historical snapshot" with no bills behind them.
- **Bookings:** fares and hotel rates are live SerpAPI data, or labelled "Estimated" when the live search fails. **Purser takes no payment.** Approval opens the airline or hotel checkout.
- **Eval runs** switch off real email, calendar, flight search and live FX, so they are deterministic and send nothing.
- Sample documents in `evals/dev/` and `evals/contracts/` are generated and marked "SYNTHETIC".

## Data permissions
- Real Gmail and Calendar are used **only for the builder's own linked account** (OAuth, Google test mode).
- Real email is sent only to recipients on file in the synthetic workspace or to addresses the builder controls.
- The builder's real NDAs were used locally for testing only and are never committed.
- No secrets are in the repo. Keys live in `.env` locally (gitignored) and in AWS Secrets Manager in production.

## Known limits
- The eval is **text-path only, single runs, 90 turns**. The voice channel uses the same engine but was not evaluated end to end.
- p95 latency is about 15 s on complex turns. Simple confirmations take about 0.1 s.
- Eval costs per task cover the text agent only. Real-time voice audio is billed separately and was not measured.
- **No Tally or Zoho integration yet.** Purser keeps its own append-only ledger. Syncing confirmed receipts to Tally/Zoho as vouchers is a roadmap item, not built. GST filing, payroll and bank reconciliation are out of scope.
- Organiser rule: no GPUs and no Amazon Bedrock. All AI runs through the OpenAI API, on CPU-only Fargate.
- CI/CD: the repository has hygiene CI (forbidden files, gitleaks). Infrastructure is Terraform, applied by hand. App deploys run from GitHub Actions on every push to `main` (`.github/workflows/deploy.yml`, OIDC role, no stored AWS keys): build, migrate, roll ECS, check `/health`. The pipeline was added on 22 Nov; its first successful run deployed `7bb2f04`.
- Infrastructure is sized for a demo: one ECS task, single-AZ RDS with 1-day backups, no CloudWatch alarms. The production steps are listed in [`PRODUCTION.md`](PRODUCTION.md) §4.
- The 90-turn eval ran on commit `8c39078`. The live build is `7bb2f04`: it adds targeted agent fixes (in `2dcc7dc`, covered by extra tests), visual-only UI fixes (ribbons behind the cards, a phone-width layout) and the deploy pipeline. No backend or agent code changed after `2dcc7dc`. The full eval was not re-run on it.
- Market figures in the README (MSME count, language reach) come from public government and census sources, linked there. The persona "Priya" is illustrative, not a customer interview.
